# ADR-002: 「手搓菜池」为核心，非 AI

**日期**：2026-08-23
**状态**：Accepted
**决策者**：用户

## Context

最初设计假设核心是 **AI 推荐菜**（基于偏好 + 健康档案）。

JTBD 调研中用户明确回答：
- #4「我会用手搓，做自己会做的菜」
- #6「根据冰箱现有的食材+自己会做的菜给出几道不重复的菜名」
- #8「自己心情 > 健康 > 新鲜 > 好吃 > 家人喜好」

**用户实际流程**是：
1. 看冰箱有什么
2. 想「我会做啥」
3. 从「我会做 ∩ 冰箱有」里随机挑一个

**不是**「让 AI 帮我推荐新菜」。

## Decision

**核心流程**：
```
「我会做」菜池 + 冰箱食材 - 最近 7 天 = 候选
                                       ↓
                                   随机抽 3 道
```

**AI 定位为聊天（不是选菜）**：放在「🤖 AI 顾问」二级按钮，跳到 chat 页。AI **不参与选菜主流程**，只在用户主动想聊时用。

## Consequences

**✅ 好的影响**
- **响应快**：本地随机 < 100ms，无网络依赖
- **零成本**：核心流程不调 AI，每次使用成本 0
- **符合用户实际习惯**：不强迫用户接受 AI 推荐
- **隐私**：核心流程不传用户数据给外部 AI

**❌ 代价**
- **菜池需要冷启动**：新用户首次进入看到空菜池 → onboarding modal 引导从 125 道勾选
- **AI 能力被闲置**：写好的 aiAdvisor 端点使用率可能低（< 30%）
- **菜池维护成本**：用户要主动增删菜，长期可能偏离实际能力

**回滚成本**：低。可以把 AI 按钮升级为主要入口，把随机降为辅助。

## 不可逆性

**完全可逆**。AI 端点已经写好，随时可以反转。

## 验证指标

- AI 按钮使用率 < 30% → 说明本地随机已满足需求
- 菜池平均 8-15 道 → 说明 onboarding 引导有效
