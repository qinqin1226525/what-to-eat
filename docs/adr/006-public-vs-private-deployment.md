# ADR-006: 公开 vs 私有部署

**日期**：2026-08-23
**状态**：Pending（决策推迟到产品验证后）

## Context

小程序有两个发布路径：
| 路径 | 受众 | 审核 | 用户增长 |
|---|---|---|---|
| (A) **公开**（提交微信审核 → 上线）| 所有人 | 必要（每次更新都要审，1-7 天）| 理论无限 |
| (B) **私有**（仅体验成员）| 你 + 30 个体验者 | 不要 | 仅小圈子 |
| (C) **半公开**（公开但小范围）| 公开上线 + 灰度发布 | 必要 | 可控 |

## Decision

**当前阶段：(B) 私有** —— 仅个人 + 体验成员使用。

**不立即公开的原因**：
- v2 是大重构，需要个人验证体验
- 公开后任何改动都要走审核（影响迭代速度）
- 隐私边界还在调整（菜池数据是否安全）

## Consequences

**✅ 好的影响**
- 迭代快：改完直接 devtools 上传 → 手机扫码就能用
- 不需要管审核规则（避免被拒）
- 隐私边界可以宽松设计

**❌ 代价**
- 用户量 = 0（无法验证规模化场景）
- 看不到真实的「别人怎么用」
- 没有「公开反馈 → 改进产品」循环

## 何时升级到 (A) 公开？

**触发条件**（全部满足）：
1. 个人连续使用 v2 ≥ 30 天
2. 核心流程跑通无 bug
3. 至少有 3 个体验成员给过正面反馈
4. 隐私/审核相关文档准备好（小程序的运营规范、用户协议、隐私协议）

## 不可逆性

**完全可逆**。从私有转公开是单向上传，不会丢失任何代码或数据。
