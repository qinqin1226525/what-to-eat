# ADR-001: 3 项 tabBar 简化架构

**日期**：2026-08-23
**状态**：Accepted
**决策者**：用户 + Claude

## Context

v1 版本（个人网页工具移植）有 6 个页面、4 个 tabBar 项：

```
tabBar v1: [选菜] [历史] [冰箱] [我的]
pages:     index  history  fridge  profile  stats  chat
```

用户反馈：
- **记不住入口**：「选菜」「历史」「冰箱」「我的」概念重叠
- **入口太多**：核心场景（饭点选菜）淹没在4 个 tab 里
- **「我的」里塞太多东西**：偏好、健康画像、seed 按钮、AI 设置混在一起

JTBD 调研发现核心 job 是「**饭点快速决定吃啥**」，其他都是辅助。

## Decision

v2 改为 **3 项 tabBar**：

```
tabBar v2: [选菜] [冰箱] [记录]
pages:     home   fridge   history  (+ profile 作为二级页 + chat 隐藏)
```

**取舍**：
- 「选菜」= 首页 = 手搓选菜（核心）
- 「记录」= 历史（含手动记录） + ⚙ 齿轮入口到「我的」
- 「AI 顾问」（聊天）「健康画像」「seed 工具」藏在二级页面，不放 tabBar

## Consequences

**✅ 好的影响**
- 认知负担从 4 个 tab 降到 3 个
- 核心场景（饭点选菜）= 第一个 tab = 一打开就能用
- 「我的」访问路径变深，但实际使用频次低，可接受

**❌ 代价**
- 老用户需要重新适应导航
- 「我的」需要2 步（记录页 → 齿轮 → profile）
- 公开测试时要重新教育用户（影响小，因为还没发布）

**回滚成本**：中等。需要重新写 app.json tabBar + 改 home 内容。

## 不可逆性

**部分不可逆**。一旦公开用户习惯了 3 tab，再改回 4 tab 需要重新设计 onboarding 引导。但因为还没上线公开，**当前可逆成本低**。
