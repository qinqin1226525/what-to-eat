# PRD: 今天吃什么 v2

**状态**：Active
**版本**：v2.0
**更新日期**：2026-08-23
**对应分支**：simplify-v2

---

## 1. 背景

「今天吃什么」是一个**微信小程序**，解决用户**饭点选菜困难**的问题。

最初版本（v1）移植自个人网页版工具，有 6 个页面、4 个 tab、125 道菜 + AI 顾问 + 健康档案 + 统计 + 手动记录。用户反馈 **太复杂、记不住入口、tab 太多**。

v2 经过 **JTBD 调研** 重新设计：核心场景是「**饭点快速、不动脑、用心**」地决定吃啥，孩子场景下要避免手机被孩子注意到。

## 2. 用户画像

**主要**：30+ 在职家长，会做饭但纠结吃什么；饭点要快；要带孩子，没法用手机太久。

**次要**：任何想**省心地从「自己会做的菜」里选**的用户，不限于家长。

## 3. 核心场景（User Stories）

| ID | 场景 | 期望结果 |
|---|---|---|
| US-1 | **饭点不知道做什么** | 5 秒内看到 3 道候选菜（来自我的菜池 + 冰箱食材）|
| US-2 | **想换换口味** | 调 AI 给灵感，看到带理由的 3 道菜 |
| US-3 | **记下今天吃了啥** | 一键记录（不弹确认 modal） |
| US-4 | **手动记录（不在菜谱库的菜）** | 历史页有「📝 手动记录」按钮 |
| US-5 | **首次使用** | onboarding 让我从 125 道家常菜里勾选我会做的 |
| US-6 | **手机被孩子看到** | 孩子不被吸引（无动画、无鲜艳色、无声音）|

## 4. 功能需求

### 4.1 手搓选菜（核心）

- **菜池管理**（`customDish` 云函数）
  - `get` / `add` / `remove` / `replace` 四端点
  - 菜池持久化在 `user_custom_dishes` 集合（按 `_openid` 隔离）
- **首页 UI**（`pages/home/home`）
  - 冰箱食材 chip 行（横滑）
  - 菜池 chip 行（横滑 + 内联 + 删除）
  - 大按钮「🎲 帮我选 3 道」
  - 小按钮「🤖 AI 顾问（聊天）」—— 跳到 chat 页
  - 最近 7 天吃过提示
- **随机选菜算法**
  - 候选 = 菜池 − 最近 7 天已抽（`meals` 集合）
  - 启发式：优先选菜名包含冰箱食材的
  - 随机洗牌取前 3 道
  - 全部候选被吃完 → 提示「加点新菜」
- **结果 modal**
  - 3 张菜卡，每张「吃这个 →」一键记录
  - 默认 `meal: '午餐'`、`status: 'confirmed'`、`date: 今天`

### 4.2 AI 顾问（聊天，可选增强）

- **触发**：首页「🤖 AI 顾问（聊天）」按钮
- **行为**：`wx.navigateTo` 跳转到 `pages/chat/chat`
- **后端**：`aiAdvisor` 云函数**默认 mode**（无 mode = 聊天分支）
- **输入**：用户问题 + 健康档案 + 今日营养
- **输出**：流式 AI 回复（聊天页打字机效果）
- **降级**：AI_KEY 未配 / 超时 → 聊天页显示「AI 暂不可用」
- **核心定位**：**AI 顾问是用户和 AI 的对话渠道**（不是帮用户选菜）—— 解读今日营养、推荐个性化菜谱、教做菜、回答营养问题

> ❌ **历史错误**：v2 PRD 早期版本把 AI 写成「💡 AI 给点灵感 + pickWithAI 选菜」，但实际用户想要的是**聊天**，不是 AI 选菜。已修正。

### 4.3 冰箱管理（次要）

- 现有 `pages/fridge/fridge`：增删食材（保持 v1 实现）
- 单独 tabBar 项

### 4.4 历史记录（次要）

- 现有 `pages/history/history`：按日期分组、删除记录
- 「📝 手动记录」按钮 + modal（v2.1 新增）
- 顶部「⚙ 设置」齿轮 → 跳 profile（健康档案 + 偏好 + dev seed 按钮）

### 4.5 Onboarding（首次使用）

- 触发：首次进入 home 且菜池为空
- UI：全屏 modal，按 role 分组展示 125 道菜
- 多选 checkbox，「跳过」 / 「保存」
- 保存 → `customDish.replace` → 写入云端

## 5. 非功能需求

| ID | 需求 |
|---|---|
| NFR-1 | **启动到能选菜 < 3 秒**（饭点场景） |
| NFR-2 | **不让孩子被吸引**：无弹跳/缩放动画、无鲜艳红绿色块、无声音反馈 |
| NFR-3 | **单页不滚动**（饭点单手操作）|
| NFR-4 | **菜池多端同步**：换手机/重装不丢数据 |
| NFR-5 | **AI 聊天可降级**：未配 API_KEY 时聊天页提示「AI 暂不可用」，不阻塞其他功能 |
| NFR-6 | **隐私**：用户菜池对其他用户不可见（按 `_openid` 隔离）|

## 6. Out of Scope（v2 不做）

- ❌ 菜谱评分 / 点赞系统
- ❌ 社区分享 / 好友互动
- ❌ 多用户协作菜池（家庭共享）
- ❌ 营养统计图表
- ❌ 月子餐 / 儿童餐 / 老人餐等场景分类
- ❌ 推送通知（云函数定时器）
- ❌ 离线模式（无网时使用）
- ❌ 视频菜谱

## 7. tabBar 设计

3 项：**选菜 / 冰箱 / 记录**

（v1 有 4 项「选菜/历史/冰箱/我的」，v2 砍掉「我的」独立 tab，合并到「记录」页右上角齿轮）

## 8. 成功指标

| 指标 | 目标 |
|---|---|
| 日均启动 | 1-3 次（早/午/晚饭点）|
| 启动 → 完成选菜 | < 10 秒 |
| 7 天留存 | > 50% |
| 菜池平均大小 | 8-15 道 |
| 「💡 AI 给点灵感」使用率 | < 30%（说明本地随机够用）|
| 手动记录占比 | < 40%（说明 125 道菜库覆盖日常）|

## 9. 技术栈

- **前端**：微信小程序（WXML + WXSS + JS）
- **后端**：微信云函数（Node.js + `wx-server-sdk`）
- **数据库**：微信云数据库（MongoDB-like，按集合分）
- **AI**：DeepSeek API（外部）
- **缓存**：本地 `dishes-data.js`（云端 seed 失败时降级）
